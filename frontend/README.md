# TrailMatch — frontend (MVP, tourist flow)

Vite + React 18 + TypeScript (strict) + React Router + TanStack Query + Tailwind. Talks to the TrailMatch backend at `/api/v1`.

## Статус (чесно)
| Що | Стан |
|---|---|
| Код сторінок, API-шару, auth | Написано |
| Синтаксична перевірка `tsc` (без залежностей) | Пройдена: синтаксичних помилок немає. Решта помилок — лише через відсутні пакети (`@types/react`, router тощо) |
| `npm install` / повний `tsc` / `vitest` / `vite build` | **НЕ запускались** (у середовищі генерації немає доступу до npm-реєстру) |
| Тест проти реального бекенду | **НЕ виконувався** |
Перші кроки: `npm install && npm run typecheck && npm test && npm run build` і виправити, що впаде (найімовірніше — дрібні помилки типів).

## Запуск
```bash
# 1) бекенд на 127.0.0.1:8000 (див. архів backend, seed_dev.py для даних)
npm install
npm run dev          # http://localhost:3000, /api проксуються на :8000 (CORS не потрібен)
npm test
npm run build
```
Docker: `docker build -t trailmatch-web .` (nginx на :8080, `/api/` → `http://api:8000`; запускайте в одній compose-мережі з backend-сервісом `api`).

## Що реалізовано (екран → маршрут)
Home `/`, Catalog `/tours` (фільтри в URL, «Показати ще»), Tour `/tours/:id` (бронювання, програма, відгуки, схожі тури), Guide `/guides/:id`, Quiz `/quiz`, Recommended `/recommended`, Login/Register `/login`, Profile `/profile` (дані, згода, квіз, бронювання + оплата, відгуки).

## Рішення та припущення
* **Не з вайфреймів / припущення:** квіз має 2 службові кроки (рівень досвіду, бюджет), бо їх вимагає бекенд (правило T-04, фільтр бюджету). Решта питань — з БД (контент pending).
* Картка каталогу = виїзд (дата + «Забронювати»).
* **Пропущено свідомо:** `City` у хедері (незрозуміле призначення, Q-7), категорії-кружки, Instagram/команда/FAQ на Home (немає в Story Map), адмін-панель (немає вайфреймів), завантаження фото у відгуки (Q-5), E2E (Playwright) — наступний крок.
* Мова інтерфейсу — українська, тексти поки inline (винести в i18n, коли визначите мови).
* Показники на сторінці туру підписані за реальними полями, бо в макеті всі підписи — «duration».

## Безпека
* JWT у `sessionStorage` (MVP) — вразливий до XSS, тому: жодного `dangerouslySetInnerHTML`, весь UGC — текст, суворий CSP в `nginx.conf`. Надійніше — httpOnly-cookie (потребує змін бекенду, CSRF, refresh).
* Приховування за роллю — лише UX; права перевіряє бекенд.
* Помилки показуються за `error.code`, а не сирим текстом сервера.
* Блок «Схожі тури» (ML) при 501/503 просто зникає, решта сторінки працює. Відповіді mock-ML позначаються банером.
* Кнопка «Оплатити» працює лише якщо бекенд має `PAYMENT_MODE=mock` (dev); інакше покаже «функція ще не налаштована».
